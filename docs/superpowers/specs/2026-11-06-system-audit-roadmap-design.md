# ZROZUMILOAI — Аудіт системи та комплексна дорожня карта розвитку

**Дата:** 2026-11-06  
**Статус:** Узгоджено / В очікуванні плану впровадження  
**Контекст середовища:** Гібридний single-VPS (16 GB RAM, 4+ vCPU, Ubuntu, Docker Compose + Caddy), локальна Ollama з обмеженням ресурсів + хмарний Google Gemini fallback, інтеграція з Open edX LMS (Tutor).

---

## 1. Резюме аудіту системи

### 1.1 Поточний архітектурний стек
- **Бекенд:** Python 3.12, Django 5.x, Django REST Framework, Celery 5.4, Redis 7.2 (брокер, бекенд результатів і кеш векторних ембедингів), PostgreSQL 16 з pgvector.
- **LLM-інференс:** Локальна Ollama (llama3.2, nomic-embed-text) та Google Gemini (2.0 Flash / 2.5 Flash Lite) через абстракцію фабрики провайдерів `resolve_provider`.
- **RAG & Пошук:** Локальний векторний пошук (pgvector CosineDistance) + Open edX Meilisearch, об'єднані за алгоритмом Reciprocal Rank Fusion (RRF).
- **Фронтенд:** React 18, Vite, React Router 6, чистий JS/JSX, єдиний монолітний `index.css` (~30 КБ), незалежний Embed-віджет (`widget.js` + `embed.html`).
- **DevOps & Безпека:** Caddy reverse proxy з TLS та лімітом тіла запиту 12MB, шифрування ключів у БД (`FIELD_ENCRYPTION_KEY`), хешування віджет-токенів (`SHA-256`), обмеження ресурсів контейнерів у `docker-compose.prod.yml`.

### 1.2 Виявлені точки оптимізації та технічний борг
1. **Цілісність резервного копіювання:** Скрипт `backup-cron.sh` та команда `create_backup` знімають дамп лише бази даних Postgres. Завантажені документи користувачів у `/app/media/workspace_documents/` залишаються поза бекапом, що створює ризик втрати файлів при відновленні на новому VPS.
2. **Монолітність фронтенду:** Компонент `ChatPage.jsx` (~730 рядків) поєднує логіку SSE-стрімінгу, буферизацію RAF, автоскрол, синхронізацію воркспейсів, запити до бекенду та рендеринг. Аналогічно `WorkspacesPage.jsx` (~600 рядків) містить всю логіку налаштувань.
3. **Наївне форматування відповідей:** Відповіді моделі парсяться за допомогою примітивного regex для жирного шрифту (`formatBoldText`). Відсутня підтримка повноцінного Markdown, списків, таблиць, підсвічування синтаксису коду та кнопки копіювання блоків коду.
4. **Обмеження RAG-пайплайну:** Підтримуються лише формати `.txt`, `.md` та `.pdf`. Відсутні поширені навчальні формати `.docx` та `.html`. Чанкінг здійснюється наївним розрізанням за фіксованою довжиною символів замість врахування структури параграфів і розділів.
5. **Відсутність локального гібридного пошуку:** Внутрішній пошук документів спирається лише на векторні ембединги, що ускладнює пошук точних шифрів, номерів дисциплін та абревіатур.
6. **Відсутність аналітичної видимості:** Викладачі та адміністратори не мають зведеної інформації про теми частих звернень студентів, рівень ескалації (handoff) та прогалини в базі знань.

### Фаза 1: Надійність даних, безпека та ядро (Data Safety & Core)

#### 1.1 Повний архівний бекап (БД + Медіа)
- **Архітектура:** Модифікація сервісу бекапів `backups/services.py` та скрипта `scripts/backup-cron.sh`.
- **Формат архіву:** Створення єдиного стиснутого архіву `zrozumiloai_backup_YYYYMMDD_HHMMSS.tar.gz`, що містить:
  - `database.sql` (PostgreSQL `pg_dump`)
  - `media/` (копія директорії `/app/media/workspace_documents/`)
  - `manifest.json` (версія схеми, дата, хеш-суми, метадані)
- **Відновлення (`restore_backup`):** Команда автоматично розгортає `database.sql` у PostgreSQL і синхронізує файли в `/app/media/`, запобігаючи битим посиланням у `WorkspaceDocument.file`.
- **Автоматична ротація:** Збереження принципу `BACKUP_KEEP_DAYS` (за замовчуванням 14 днів) для очищення старих архівів `.tar.gz`.

#### 1.2 Оголошення HNSW індексу в моделі `DocumentChunk`
- **Зміни:** Внесення `pgvector.django.HnswIndex` у `DocumentChunk.Meta.indexes`:
  ```python
  indexes = [
      models.Index(fields=['workspace']),
      HnswIndex(
          name='chunk_embedding_hnsw_idx',
          fields=['embedding'],
          m=16,
          ef_construction=64,
          opclasses=['vector_cosine_ops'],
      ),
  ]
  ```
- **Результат:** Автоматичне створення та валідація індексу засобами Django на будь-якому новому середовищі без ручних SQL-скриптів.

#### 1.3 Оптимізація індексів аналітики
- Додавання складених індексів у модель `WorkspaceChatLog`:
  - `(workspace, created_at)` для швидкої фільтрації аналітики за часовими діапазонами.
  - `(workspace, needs_handoff)` для швидкого вибору черги нерозкритих тем.

### Фаза 2: Рефакторинг фронтенду, UX та повноцінний Markdown

#### 2.1 Декомпозиція `ChatPage.jsx`
- Виділення автономних компонентів у `frontend/src/components/chat/`:
  - `ChatContainer.jsx`: координуючий каркас.
  - `MessageList.jsx`: рендеринг списку повідомлень із віртуалізацією/плавним скролом.
  - `ChatMessage.jsx`: картка повідомлення (аватари, таймстемп, цитати джерел, кнопки 👍/👎, статус ескалації).
  - `ChatInput.jsx`: багаторядкове поле вводу (Enter для відправки, Shift+Enter для нового рядка, авторозширення, кнопка зупинки генерації).
  - `ModelSelector.jsx`: вибір активної моделі та воркспейсу з колірними бейджами провайдерів.
  - `SourceCitations.jsx`: інтерактивний список першоджерел RAG із показом релевантності та назви документа.
- Створення кастомних хуків у `frontend/src/hooks/`:
  - `useChatStream.js`: інкапсуляція SSE, буферизації `requestAnimationFrame`, `AbortController`, накопичення тексту відповіді та обробки обривів з'єднання.
  - `useChatScroll.js`: відстеження положення користувача, автоскрол та плаваюча кнопка повернення вниз.

#### 2.2 Повноцінний та безпечний рендеринг Markdown
- **Бібліотека:** Впровадження легковажного `markdown-to-jsx` (або `react-markdown` + `rehype-sanitize`).
- **Можливості:**
  - Підтримка списків, заголовків, жирного/курсивного накреслення, таблиць та цитат.
  - Підсвічування блоків коду (fenced code blocks) із визначенням мови програмування.
  - Кнопка копіювання коду в буфер обміну з візуальним підтвердженням («Скопійовано»).
  - Захист від XSS та безпечні зовнішні посилання (`rel="noopener noreferrer" target="_blank"`).
- **Синхронізація з Embed Widget:** Перенесення базових стилів форматування списків і коду у `embed.css` для однакового відображення у віджеті Open edX.

#### 2.3 Модуляризація CSS
- Розділення монолітного `index.css` (30 КБ) на логічні модулі стилів:
  - `styles/base.css` (змінні, скидання, типографіка).
  - `styles/chat.css` (стилі діалогового інтерфейсу).
  - `styles/workspaces.css` (інтерфейс налаштувань).
  - `styles/components/markdown.css` (стилізація коду, таблиць і списків).

### Фаза 3: Модернізація RAG, нові формати та відмовостійкість LLM

#### 3.1 Підтримка нових форматів документів
- **Розширення `text_extractor.py`:**
  - Додавання екстракції з `.docx` за допомогою чистого Python-пакета `python-docx` (вилучення параграфів і таблиць без втрати тексту).
  - Додавання екстракції з `.html` / `.htm` (очищення від DOM-скриптів, вилучення смислового контенту лекцій).
- **Стійкість обробки:** Помилка на окремій сторінці чи таблиці не перериває обробку документа повністю — фіксується часткове вилучення з інформативним попередженням у журналі.

#### 3.2 Структурний (семантичний) чанкінг
- Заміна фіксованого розрізання символів у `chunker.py` на структурний поділ:
  - Пріоритетні межі розбиття: Markdown-заголовки (`#`, `##`), подвійні переноси рядків (параграфи), пункти списків.
  - Збереження контексту: метадані чанка (назва поточного розділу та сторінка) зберігаються у `DocumentChunk` для точного цитування («Розділ 3, стор. 12»).

#### 3.3 Локальний гібридний пошук (Postgres Full-Text + pgvector)
- **Архітектура:**
  - Генерація повнотекстового індексу `tsvector` для `DocumentChunk.content` у PostgreSQL.
  - Паралельний або послідовний пошук: векторний (косинусна схожість) + лексичний (`to_tsquery` з підтримкою українського та англійського стемінгу).
  - Злиття результатів локального пошуку через Reciprocal Rank Fusion (`fusion.py`) перед комбінуванням із Meilisearch (якщо підключено).
  - **Перевага:** Гарантоване знаходження точних шифрів, номерів нормативних актів, абревіатур і формулювань.

#### 3.4 Відмовостійкість LLM та прозорий Fallback (Circuit Breaker)
- **Логіка у `backend/llm/chat.py`:**
  - Якщо вибрано локальну Ollama, але сервіс повертає помилку з'єднання, таймаут або 503 (перевантаження черги моделі):
  - Перевіряється наявність налаштованого резервного ключа Google Gemini у поточному воркспейсі або в змінних середовища.
  - Запит безшовно перенаправляється на модель Gemini з додаванням службового прапорця `provider_fallback: true` у метадані стріму.
  - Подія фіксується у системних логах без аварійного обриву зв'язку зі студентом.

### Фаза 4: Аналітичний дашборд та звітність для викладачів/адміністраторів

#### 4.1 Бекенд-агрегація та API
- Новий контролер `GET /api/workspaces/<id>/analytics/`:
  - Фільтри за датою: `today`, `7d`, `30d`, довільний інтервал `start_date` .. `end_date`, фільтр за `openedx_course_id`.
  - Розрахунок ключових метрик (KPIs):
    - Загальна кількість запитів і унікальних сесій.
    - Коефіцієнт ескалації (Handoff Rate %: частка відповідей із низькою впевненістю RAG).
    - Індекс корисності (CSAT: % оцінок 👍 серед усіх оцінених відповідей).
  - **Черга нерозкритих тем (Knowledge Gaps):** Вибірка запитів, де `needs_handoff=True` або отримано 👎, згрупованих за схожістю.
  - **Експорт:** Можливість скачування CSV-звіту з анонімізованими ідентифікаторами студентів для звітності кафедри/курсу.

#### 4.2 Фронтенд-інтерфейс аналітики
- Додавання розділу «Аналітика воркспейсу» у веб-панель:
  - Віджети показників (KPI Cards) із відображенням відсотків та динаміки.
  - Інтерактивна таблиця прогалин знань: кнопка швидкої дії «Завантажити матеріал у RAG» для закриття виявленої прогалини безпосередньо зі сторінки аналітики.
  - Візуалізація навантаження за годинами/днями для моніторингу піків активності перед екзаменами та дедлайнами курсів.

## 3. Критерії успішності (Acceptance Criteria)

1. **Цілісність бекапів:** Повний цикл створення бекапу та його відновлення на чистій системі (`restore drill`) успішно відновлює як дані таблиць PostgreSQL, так і фізичні файли документів у `/app/media`.
2. **UX та Markdown:** Повідомлення чату у веб-панелі та віджеті коректно рендерять форматований текст, списки, таблиці та блоки коду з можливістю їх копіювання в один клік без XSS-вразливостей.
3. **Модульність коду:** `ChatPage.jsx` декомпоновано на окремі модулі розміром до 150-200 рядків кожен; логіка стрімінгу та скролу винесена у протестовані хуки.
4. **Гнучкість RAG:** Пайплайн індексації успішно розбирає `.docx` та `.html`; комбінований пошук знаходить точні збіги термінів через локальний повнотекстовий індекс.
5. **Відмовостійкість:** При штучному вимкненні або перевантаженні Ollama чат автоматично продовжує відповідати через Gemini (за наявності ключа) без помилки для користувача.
6. **Аналітика:** Викладач воркспейсу має наочний дашборд із переліком питань, на які штучний інтелект не зміг знайти відповідь у документах курсу.
